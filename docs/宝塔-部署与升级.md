# 一方菜园 V5.3 · 宝塔部署与升级

这是一套 FastAPI + SQLite 应用，前端已经构建完成。宝塔服务器只需 Python 3.10 或以上，不需要 Node.js。当前包提供三维菜园、横竖屏自适应、手动生长阶段、库存出入库、数字二维码、种植历史、公开天气、昼夜场景、作物生长照片记录、物资多图档案、七牛云图片上传，以及随站点本地发布的 15 种虫害 + 15 种病害图鉴。

网站可以公开查看，但所有会改变数据的管理操作都需要四位数字密码。密码验证后通过 HttpOnly Cookie 保持 30 天，适合公开网站由少数管理者维护。

## 已经部署 install 包的升级（按这一节操作）

你之前已经部署过 `grow-garden-v2-install-20260911.zip`、v3、v4、v5、v5.1 或 v5.2 包时，只需要用 `grow-garden-v5.3-upgrade-20260913.zip` 覆盖程序文件。升级包不包含 `data` 目录，因此不会覆盖原来的 `data/grow.db`。

### 1. 停止并备份

在宝塔“网站 → Python 项目”中停止 `grow` 项目，然后备份整个目录：

```text
/www/wwwroot/grow/data
```

### 2. 用 upgrade 包覆盖程序

上传当前的 `grow-garden-v5.3-upgrade-20260913.zip`，在 `/www/wwwroot/grow` 目录选择“解压到当前目录”，允许覆盖同名的 `app`、`static`、`requirements.txt` 等程序文件。

不要上传 install 包，也不要把 `data/grow.db` 解压到旧项目中。

### 3. 用项目根目录 `.env` 配置

新版会自动读取 `/www/wwwroot/grow/.env`。因此宝塔 Python 项目的“环境变量”可以继续选择截图中的“无”，不需要逐项添加。**不要直接修改 `.env.example` 期待它生效**；请复制一份并命名为 `.env`，再修改 `.env`。

在宝塔文件管理器中：复制 `/www/wwwroot/grow/.env.example`，将副本命名为 `/www/wwwroot/grow/.env`，然后编辑 `.env`。程序会在启动时读取它；如果同名变量同时存在于宝塔环境变量，宝塔环境变量优先。

按下面的规则处理旧变量：

| 环境变量 | 处理方式 |
| --- | --- |
| `GROW_STATIC_DIR=static` | 删除。新版默认目录就是 `/www/wwwroot/grow/static/client` |
| 没有 `GROW_STATIC_DIR` | 不用添加，保持默认即可 |
| `GROW_STATIC_DIR=/www/wwwroot/grow/static/client` | 可以保留 |
| `GROW_DATA_DIR` 或 `GROW_DB_PATH` | 如果旧项目使用过自定义数据位置，保持原值，不要随意删除 |

如果你愿意继续使用宝塔环境变量，下面两项也可以在那里设置；否则直接写进 `.env`：

```text
GROW_ADMIN_PIN=你自己的4位数字
GROW_ADMIN_SESSION_SECRET= # 填写自己的随机字符串
```

`GROW_ADMIN_PIN` 必须正好四位数字，请自行配置，示例文件不提供默认密码。修改 `.env` 后必须保存并重启 Python 项目才会生效；修改 PIN 会让旧管理会话失效。

图片上传还需要在 `.env` 中填写七牛云变量。不要把 AK/SK 写进前端文件、网页代码或公开的 `.env.example`：

```text
QINIU_ACCESS_KEY= # 填写自己的 AccessKey
QINIU_SECRET_KEY= # 填写自己的 SecretKey
QINIU_BUCKET=your-bucket
QINIU_REGION=z0
QINIU_UPLOAD_URL=https://up-z0.qiniup.com
QINIU_PUBLIC_BASE_URL=http://images.example.com
QINIU_TOKEN_TTL=1800
QINIU_MAX_IMAGE_BYTES=2097152
QINIU_MAX_SOURCE_IMAGE_BYTES=16777216
QINIU_MAX_IMAGE_EDGE=2048
```

这里 `z0` 对应七牛的华东-浙江区域，`QINIU_PUBLIC_BASE_URL` 要填写图片访问域名而不是宝塔网站域名。你提供的域名当前按 `http://images.example.com` 使用，不要填成 HTTPS；旧数据库中的 `https://images.example.com/...` 图片地址会由后端自动转换为 HTTP，避免证书域名不匹配。如果以后改用已经配置有效证书的其他七牛访问域名，再修改这个变量。如果只填了七牛变量而未设置 AK/SK，图片上传按钮会提示“七牛云上传尚未配置”。

图片选择时只在页面本地预览，点击保存后浏览器才把原图发到本站后端；后端再将处理结果上传七牛，所以七牛空间通常不需要为浏览器上传配置 CORS。服务端会将最长边限制在 2048 像素以内；不超过该尺寸时保持原始像素，以无损 WebP 编码，最终文件严格不超过 2 MB。超过 2048 像素的原图会先等比例缩小，这是唯一可能改变像素的步骤。图片对象会自动使用以下目录：`grow/plots/{地块编号}/日期/`、`grow/crops/{地块编号}/日期/`、`grow/crops/{地块编号}/growth/日期/`（生长照片）、`grow/supplies/{物资编号}/日期/`、`grow/threats/{图鉴资料编号}/日期/`。

### 4. 宝塔重新安装依赖

V5.3 延续图片处理依赖 Pillow。覆盖升级包后请在宝塔中重新安装 `requirements.txt`，再重启项目：

1. 打开“网站 → Python 项目 → grow → 设置/配置”。
2. 找到“依赖文件/项目依赖”，确认填写：

   ```text
   /www/wwwroot/grow/requirements.txt
   ```

3. 点击“安装依赖”或“重新安装依赖”（不同宝塔版本按钮名称可能略有不同），等待日志显示安装完成。
4. 回到项目列表，点击“重启”。不要删除项目虚拟环境，也不要删除 `data` 目录。

如果面板没有安装按钮，在宝塔终端中进入项目目录，用**宝塔 Python 项目所选择的同一个 Python 解释器**执行：

```text
cd /www/wwwroot/grow
python -m pip install -r requirements.txt
```

不要用系统中另一个 Python 的 `pip`，否则依赖可能安装到了错误的环境。

### 5. 重启并检查

重启 Python 项目后依次检查：

1. 打开 `https://你的域名/health`，应返回 `status: ok`。
2. 打开网页，点击“解锁管理”，输入刚设置的四位密码。
3. 点击“同步”，检查原有地块、二维码、库存和历史记录。

浏览器仍显示旧页面时，执行一次强制刷新。管理密码验证成功后当前设备保持 30 天。

首次启动 V5.3 时会自动完成必要的数据库迁移，并在 `data/backups/` 保存升级前备份；SQLite 用户版本为 7。库存流水会保存物资名称和单位快照，物资删除后不再与农事记录、其他流水互相阻塞。物资删除后会立即从网页列表消失；“最近出入库”中的每条流水也可以单独删除。删除流水只删除历史显示，不会改动当前库存，也不会删除关联农事记录。作物详情页的“拍照记录”可以反复添加生长照片、时间和备注；物资编辑页可以维护多张图片。种子关联是可选快照，不是作物删除或种子删除的前置条件。作物、地块、物资和图鉴中的图片均可点击查看大图。

## V5.3 病虫害图鉴

网页的“病虫图鉴”入口内置原来的 30 条资料（15 种虫害 + 15 种病害），可以搜索名称、别名或适用作物。图鉴页只负责资料查看和管理，支持新增、编辑、删除；不会从图鉴页创建农事记录。只有进入具体作物详情，在“病虫草害”操作中才可以选择图鉴条目并关联当前作物。30 张清晰图片已随站点下载并发布在 `static/client/threats/`，页面运行时不请求 Wiki；每张卡片保留原始来源页和许可说明，完整清单见 `病虫害图鉴图片来源与许可-v5.3.md`。删除图鉴资料只隐藏资料，不会删除已经存在的作物病虫害记录。

## 全新安装

1. 上传当前目录下的 **install** 包到 `/www/wwwroot/grow` 并解压。不要把 `deploy/archive/` 中的历史包用于新安装。
2. 将 `data` 目录及内部文件的所有者、用户组设置为 Python 项目的运行用户（通常为 `www`）；目录权限 `755`，数据库文件权限 `644`。SQLite 需要对数据库所在目录有写权限，以创建事务日志。
3. 在项目根目录复制 `.env.example` 为 `.env`，填写自己的四位密码；需要图片时再填写七牛云 AK/SK。`.env` 建议只允许运行用户读取。
4. 在“网站 → Python 项目”添加项目：

| 设置项 | 内容 |
| --- | --- |
| 项目目录 | `/www/wwwroot/grow` |
| 运行用户 | `www`（或已设置文件权限的同一用户） |
| Python | 3.10 或以上 |
| 依赖文件 | `/www/wwwroot/grow/requirements.txt` |
| 启动方式 | 命令行 |
| 启动命令 | `python -m uvicorn app.main:app --host 127.0.0.1 --port 8010` |
| 配置文件 | `/www/wwwroot/grow/.env`（宝塔环境变量可选“无”） |
| 管理密码 | `GROW_ADMIN_PIN=自己的4位数字`；建议同时设置 `GROW_ADMIN_SESSION_SECRET=长随机字符串` |

5. 在 Python 项目绑定自己的域名，代理到本机 `8010` 端口，并启用 HTTPS。
6. 打开 `/health` 应看到 `status: ok`。打开网站后点击右上角“解锁管理”，输入四位密码后再点击“新增地块”，建立自己的菜园。接口说明在 `/api/docs`。

页面和当前菜园数据可以公开查看；新增、编辑、删除、库存、二维码和天气刷新等写操作统一受管理密码保护。解锁成功后当前设备保持 30 天，点击“管理已解锁”可立即锁定；更换 `GROW_ADMIN_PIN` 或 `GROW_ADMIN_SESSION_SECRET` 后，旧会话也会失效。若需要完全限制网页访问，再叠加宝塔网站访问控制；码牌访问会遵循相同的访问限制。

## 在宝塔数据库页面直接添加 SQLite

使用 Linux 宝塔面板的 **数据库 → SQLite → 添加数据库**，数据库路径选择：

`/www/wwwroot/grow/data/grow.db`

如果只是要添加一个全新的空库，下载项目根目录的 `grow-empty-v5.3-20260913.db`，将它作为**单独的数据库文件**上传或放到目标目录，再在宝塔 SQLite 页面选择这个文件。不要把 ZIP 压缩包、项目目录或 SQL 文本当作数据库文件。该文件不是加密文件，文件头为标准 `SQLite format 3`，当前没有地块、物资和农事记录，但包含 30 条可编辑的图鉴资料。它只适合全新安装；已有菜园不要用它覆盖原来的 `data/grow.db`。

数据库名可填写 `grow`。部分版本还要求填写备注；按界面填写即可。不要在 MySQL 页面导入此文件，不要选择 ZIP、SQL 文本或目录。宝塔官方论坛已确认 SQLite 管理入口自 Linux 面板 9.2 提供：[宝塔官方说明](https://www.bt.cn/bbs/thread-138274-1-1.html)。

文件已完成以下检查：标准 `SQLite format 3` 文件头、UTF-8 编码、`PRAGMA integrity_check = ok`、外键检查无错误、`journal_mode=DELETE`、版本号 7。当前表结构不使用 SQLite 3.8.0 才支持的部分索引，可兼容宝塔 SQLite 3.7.17 的管理器。它是实际的数据库二进制文件，不是改了后缀的 SQL 文本。运行期间可能短暂出现事务日志；数据库空闲时不依赖 WAL/SHM 旁路文件。

如果宝塔提示数据库繁忙，先停止 Python 项目后添加，再启动。若提示只读，请同时检查数据库文件和父目录是否属于运行用户。不要同时通过数据库管理器和网页修改同一条记录。

不同面板版本、操作系统和 SQLite 管理插件的界面可能不同。本版本已验证数据库文件格式，未连接你的宝塔服务器进行面板实测。

## 手动管理生长期

选地块 → 右侧“生长阶段” → 选择阶段 → 保存。可以按实际情况前进或回退，阶段变化会自动生成农事记录，并改变 3D 作物长势。阶段进度用于界面示意，不是根据天数自动推算的成熟度。

湿度是人工观测值，浇水记录不会凭空增加湿度。更换蔬菜时点击“开始新一茬”，旧种植记录保留，上一茬病虫问题归档；地块二维码继续绑定相同地块。

## 库存入库和领用

在“物资库存”输入清单，例如：

```text
腐熟有机肥 5 千克
黄色粘虫板 20 张
青菜种子 2 包
```

点击“识别清单”，核对名称、数量、单位和分类后确认入库。同名、同分类、同单位自动累加；单位不同时分开保存，不自动换算包装规格。分类是按名称推测的，可以在确认前修改。无法识别的行会明确报错，不会猜测数量后直接入库。

物品右侧“编辑”可以修改名称、分类、单位、库存和备注；“出入库”可登记补货或领用。记录施肥、打药等农事时可选择库存物品，填写数量，保存时同步扣减。库存不足会阻止整次保存；删除关联农事记录时，仍存在的物资会退回相应库存，已经删除的物资则只保留原记录和流水。物资支持直接删除、重新新增和修改，历史流水保留发生当时的名称、单位和结存，不会反向锁住物资删除。

## 数字二维码

- 已有纯数字二维码：在网站“数字码牌”打开相机扫码，也可识别上传的二维码图片，或输入编号。
- 新制作二维码：先绑定编号，再点击“码牌”下载二维码。二维码内容为当前域名的 `/q/001` 等链接。生成码牌时请使用正式域名访问网站。
- 用微信或手机相机扫描链接码，会直接打开其绑定地块。纯数字内容没有网址，外部扫描器无法自动知道应打开哪个网站，需要在本网站内识别。
- 未绑定码会进入绑定界面；换绑、解绑前会显示确认信息。删除或归档地块会自动解除相关绑定。
- 摄像头需要 HTTPS 和浏览器相机权限；无法开启时可输入编号或上传图片。扫码图片在浏览器内处理，不上传服务器。

3D 菜园为布局和长势示意，支持旋转、缩放、漫游及全屏；横屏设备会优先使用更宽的场景比例，手机和网页窗口变化时会自动重新适配。场景标题直接显示当前时间对应的“白天 / 夜间”，天气控件可选择“实时天气 / 晴天 / 雨天 / 雾天”，默认跟随当前记录。解锁管理后点击“编辑位置”，拖动地块即可调整布局，松开后自动保存。地块真实面积以资料中的数字为准。

## 天气和昼夜场景

天气默认从公开的 [Open-Meteo Forecast API](https://open-meteo.com/en/docs) 获取绍兴越城区的当前天气和每日预报，不需要单独申请 API Key。后端会缓存每日结果，页面中的天气卡片、降雨/风力提示和三维场景会跟随返回的天气状况变化；日出到日落显示白天，其他时间显示夜景。首次部署或天气过期时，登录管理后点击天气卡片的刷新操作即可更新；接口失败时保留最近一次成功缓存，并在页面提示状态。
